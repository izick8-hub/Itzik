# מואני, סיום קנייה ועדכון קיצור הדרך

## הפעלה בפרויקט Supabase הקיים

הקוד החדש נשלח ל־GitHub; הפעלה של סיום ללא קבלה בענן דורשת פעולה נוספת בפרויקט הקיים:

1. Supabase Dashboard → **SQL Editor → New query**.
2. העתיקו את **כל** `shopping/supabase/migrations/202611110001_finish_without_receipt.sql` ולחצו **Run**.
3. הקובץ מניח ששני ה־migrations הקודמים כבר הותקנו (כפי שנדרש לסנכרון הקיים). אין להריץ שוב את קובץ ההקמה, למחוק נתוני אתר, ליצור בית חדש או להירשם מחדש.
4. הקובץ משנה רק את פונקציית השמירה המאומתת כדי לתמוך ב־`completeList`. הוא אינו מוחק רשימות, אינו מסמן מוצרים אוטומטית ואינו יוצר קבלות או מחירים. אפשר להריצו שוב בבטחה.

אם ה־migration לא הופעל, ניסיון סיום בענן מציג הנחיה להתקין אותו ואינו מדווח שהקנייה הסתיימה. המצב המקומי תומך בסיום בלי Supabase.

## סיום וקבלה בדיעבד

- ברשימה פעילה נוסף **סיום קנייה ללא קבלה**. הרשימה נשארת בהיסטוריה עם כל הכמויות וסימוני האיסוף הקיימים, גם מוצרים שלא סומנו. אפשר מיד ליצור רשימה חדשה.
- בכל קנייה שהסתיימה מופיע **העלאת קבלה בדיעבד** בהיסטוריה. אם כבר נשמרה טיוטה, הכפתור פותח אותה; אחרת נפתחת קבלה חדשה המחוברת לקנייה הנכונה, גם כשכרגע נבחרה רשימה חדשה אחרת.
- המחירים וההוצאות ממשיכים להתבסס רק על קבלות מאושרות. סיום ללא קבלה אינו ממציא הוצאה של אפס או משנה מחיר קודם.
- בעדכון הזה לא הוגדר ספק AI חדש ולא אומת OCR מול שירות חי. מסך הקבלה הקיים, ההזנה הידנית והחיבור האופציונלי נשארו. תמונות קבלות ונתוני משתמש אינם מועברים ל־Git.

## מואני וההתראות

ארבע וריאציות אמנות חדשות נוצרו לפי איורי מואני שסיפק המשתמש: עם שקית קניות, מציצה מעל כרטיס עדכון, חוגגת ליד סל ונחה ליד קבלה. כולן נשמרות באטלס שקוף אחד `public/moani-atlas.png`, ומוצגות דרך `components/Moani.tsx`. הדמויות הזוגיות נשמרו.

מואני מופיעה באזור הבית, ברקעים עדינים, במסכים ריקים, בסיום קנייה, בהודעות, במרכז העדכונים, בהגדרות ובתחתית האתר. איורים דקורטיביים מוסתרים מקוראי מסך ואינם תופסים לחיצות.

התראות חדשות פועלות **בתוך האתר כשהוא פתוח**:

- יוצר הרשימה רואה „מואני מעדכנת: רשימה חדשה נוספה לחמישי הקרוב”, או את התאריך שנבחר אם אינו חמישי הקרוב.
- המשתמש השני המחובר לאותו בית מקבל הודעה ומונה בפעמון על רשימות ומוצרים חדשים שמתקבלים בסנכרון.
- תוספות סמוכות לאותה רשימה מצטברות להודעה „נוספו X מוצרים חדשים לרשימה”. שינוי כמות, סימון ומחיקה אינם נחשבים מוצרים חדשים. טעינה ראשונה אינה מייצרת מבול התראות על כל ההיסטוריה. הוספות של המשתמש עצמו אינן יוצרות גם התראה מרוחקת כפולה.
- הפעמון מאפשר לפתוח את הרשימה הרלוונטית ולנקות את ההודעות. העדכונים נשמרים בזיכרון ההפעלה הנוכחית, לא בתיבת הודעות בענן.

אין כאן התראות Push של iOS/Android כשהאתר סגור, אין בקשת הרשאת התראות ואין הבטחה לפעילות ברקע כשהטלפון משעה את האתר.

## מדוע קיצור הדרך לא הראה עדכון

לפני ה־Push העדכון לא היה מפורסם. בנוסף, אתר שהוסף למסך הבית יכול להישאר פתוח עם קוד של גרסה קודמת.

בגרסה הזאת:

- מספר גרסה (SHA קצר של ה־commit) מופיע בתחתית האתר ובהגדרות. GitHub Actions מספק אותו בזמן הבנייה.
- `version.json` נקרא מהרשת ללא מטמון ונבדק גם בחזרה לאפליקציה. הוא אינו נכנס ל־precache של ה־service worker.
- אם השרת מפרסם גרסה שונה, מופיעה הודעת מואני עם **טעינת העדכון**. אין רענון אוטומטי באמצע טופס, והכפתור חסום בזמן שמירה או כשפתוחה עריכת רשימה/מוצר/קבלה. נתוני הדפדפן אינם נמחקים.
- בהגדרות יש **בדיקת עדכון לאתר**. הצלחת הבדיקה מוצגת רק אחרי קריאת metadata תקינה מהרשת.
- טעינת מסמכי HTML מבקשת revalidation; קובצי גרסה, תשובות Supabase וקבלות אינם מוגשים ממטמון הנתונים הסטטי. מטמוני הפיטנס אינם נמחקים.

אחרי פרסום מוצלח ב־Actions יש לרענן פעם אחת את קיצור הדרך הישן כדי לקבל גם את מנגנון העדכון החדש. אם עדיין מופיעה גרסה ישנה, ניתן לפתוח **באותו דפדפן** את נתיב הקניות עם query ייחודי, לדוגמה `?v=<commit>`, בלי למחוק את הקיצור או נתוני האתר. מספר הגרסה מאפשר להשוות בין שני הטלפונים. הצלחת Push לבדה אינה הוכחת פריסה.

## בדיקות

- `npm test`: מסלול סיום, חוסר בקבלה, שמירת מוצרים, התראות ותאריך נכון, קיבוץ הודעות, מניעת כפילויות ומעקב שני לקוחות.
- `npm run test:postgres`: שלושת ה־migrations על PostgreSQL אמיתי. בין היתר נבדקים סיום ללא קבלה, חוסר במחיר פיקטיבי, סיום חוזר, קבלה בדיעבד לקנייה ישנה, שמירת הרשימה החדשה והגנה מבית זר.
- `npm run test:e2e`: גם מסלול משתמש מלא לסיום/רשימה חדשה/קבלה ישנה, פריסות 320–1440px, מואני ומרכז העדכונים, ועדכון metadata אמיתי דרך service worker פעיל תוך שמירת נתוני דפדפן.
- `npm run test:cloud-browser`: ממשק ענן מול HTTP מדומה, כולל סיום ללא קבלה בלי שינוי הגיבוי המקומי. בדיקות אלו משתמשות ב־URL ובמפתח פיקטיביים בלבד, ואינן אימות של פרויקט הייצור.

סנכרון והתראות בשני הטלפונים האמיתיים, פריסה ציבורית והתקנה בפועל ב־Safari דורשים אימות חי. אף אחת מהבדיקות המקומיות אינה מוצגת כהוכחה להם.
